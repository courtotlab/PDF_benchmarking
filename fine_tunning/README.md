### 1.2 prepare input pickles

Example qsub file: `/u/lsong/qsub-scripts/create_input_pkl.sh`

After we have the input PDFs, since Gemma3 is a vision model, we need to convert the PDFs to PNGs using the Python script `/u/lsong/labspace/git_repo/PDF_benchmarking/fine_tunning/create_input_dict.py`. GPU is not required to run this script; however, because the PNG files are relatively larger than the PDFs, a minimum of 16 GB of memory is recommended.

The PNGs will be stored under `/.mounts/labs/courtotlab/private/jweile/projects/lei_mockup_generator/out*/png/`, and the output pickle file will be stored at the `pkl_dir` defined in the Python script. This script will generate a pickle file containing 1,000 training-ready samples. Because hospitals are using different formats of templates, the expected keys can be found at `PDF_benchmarking/getJSON/hospitals` with their matched hospitals as the filenames.

They are all in the format of: 
``` 
    {           
        "messages": [
            {
                "role": "system",
                "content": [{"type": "text", "text": sample["system_message"]}],
            },
            {
                "role": "user",
                "content": [{
                        "type": "text",
                        "text": sample["user_prompt"],
                    },
                    {
                        "type": "image",
                        "image": sample["image"], # in format of image paths
                    }, #more images here
                    ]
            },
            {
                "role": "assistant",
                "content": [{"type": "text", "text": sample["expected_report"]}], #this is expected results
            },
        ],
    }
```

Parameter settings:
```
wanted_count = 1000 #number of samples to generate
pkl_dir = "/u/lsong/labspace/lei_notebook/data/" #directory to save output pkl files
template_path = f"{script_path}/getJSON/hospitals/" #directory to hospital templates
mock_data_dir = "/.mounts/labs/courtotlab/private/jweile/projects/lei_mockup_generator/out2/"  #directory to input pdfs and output pngs
script_path = "/u/lsong/labspace/git_repo/PDF_benchmarking" #current project path in order to import local modules
```

## 2. Training LoRA
### 2.1 download model from HuggingFace
Because the GPU worker has no access to the external internet, we need to download the model from Hugging Face first via CLI commands. It is recommended to download the model in the scratch directory and redirect the Hugging Face cache directory. In `/.mounts/labs/courtotlab/scratch/`, run:
```
hf download google/gemma-3-27b-it
```

### 2.2 running training
Example qsub file: `/u/lsong/qsub-scripts/train_lora.sh`

After we have created the input datasets and downloaded the models, we are ready to train LoRA on these PNGs. This script trains the Gemma3 base model and generates an adapter model: `/u/lsong/labspace/git_repo/PDF_benchmarking/fine_tunning/train_lora.py`. Because we start to load models and train them, a GPU worker (A100 or H100) is recommended for this step.

The running time depends on the sample size. The average running time for 1,000 samples is approximately 10,000 seconds. The output LoRA will be stored at `/.mounts/labs/courtotlab/scratch/lora/{lora_name}`.

parameter settings:
```
wanted_count = 1000   #number of samples to use for training LoRA
#loading training data
pkl_dir = "/u/lsong/labspace/lei_notebook/data/" #directory to load input pkl files
# Hugging Face model id
model_name = "gemma-3-27b-it" # select from google/gemma-3-27-it, gemma-3n-E2B-it-finetuned
model_path = f"/.mounts/labs/courtotlab/scratch/{model_name}/" #directory to load base model, the model should be downloaded from Hugging Face by hf cli first
lora_output_dir = "/.mounts/labs/courtotlab/scratch/lora/" #directory to save LoRA adapter model
lora_name = f"{lora_output_dir}{model_name}{wanted_count}ct_lora" #name of the LoRA adapter model
```

## 3. Preparing the test dictionary
Example qsub file: `/u/lsong/qsub-script/create_test_pkl.sh`

Similar to the training dataset generated during the training phase, a new test dataset also needs to be generated for testing, except there are no assistant prompts available for the model. This is done by the script `/u/lsong/labspace/git_repo/PDF_benchmarking/fine_tunning/create_test_dict.py`. The `expected_report` will still be available but will be stored as a separate key in the final dictionary. It also outputs a pickle file. Similar to the step for creating the training dataset, a GPU is not required to run this script; however, because the PNG files are relatively larger than the PDFs, a minimum of 16 GB of memory is recommended.

The PNGs will be stored under `/.mounts/labs/courtotlab/private/jweile/projects/lei_mockup_generator/out*/png/`, and the output pickle file will be stored at the `pkl_dir` defined in the Python script. This script will generate a pickle file containing 1,000 samples. Formatting to OIA messages will be performed in the next step.

The format of the output dictionary will be:

```
        "image": png_path_lst,
        "mock_uuids": keys

```


## 4. Running the base LLM with LoRA and test dictionary
Example qsub file: `/u/lsong/qsub-script/run_finetuned_model_only.sh`

This script will send the PNGs and prompts into Gemma3 and compare the outputs with the expected results filtered according to the hospital template. Formatting dictionaries into OIA messages is also happens in this step, because the sample UUIDs is not relavent to the report content, but needed for tracking matched elements (expected results, responses, OIA messages, etc). Similar as generatig the training dataset, the `expected_report` json will be filtered according to `PDF_benchmarking/getJSON/hospitals`. The `response` and `expected_report` will be stored in the output pickle file. This is done by the Python script `/u/lsong/labspace/git_repo/PDF_benchmarking/fine_tunning/run_fine_tuning_model_only.py`. The generated output will be stored at `/u/lsong/labspace/lei_notebook/data/output_{model_name}_{wanted_count}ct.pkl`. This pickle file will include the prediction results and expected results in the format of a list of dictionaries. Because this step requires running model and inference expected json, it requires running on GPU workers. 

The format of the output dictionary will be:
```
[
    {
    "response": response,
    "expected_report": expected_report  # filtered json from the json generating the PDF
    },
    ...
]
```

parameter settings:
```
wanted_count = 200   #number of samples to run through the model, can be adjusted based on available memory
```

## 5. Analyzing and visualizing of the results
### 5.1 Compare model responses against expected results
Example qsub file: `/u/lsong/qsub-scripts/compareJSON_linghao.sh`

The model responses and expected results will be parsed into JSON format and then compared against each other. The input JSONs (responses and expected results) will all be parsed into lowercase and filtered against the hospital template again. Then, statistical measures will be calculated—for example: false positives, false negatives, accuracy, F1 scores, etc.—and formatted into a CSV file. All of these analyses are done by the Python script `/u/lsong/labspace/git_repo/PDF_benchmarking/getJSON/compareJSON_linghao.py`. 

In this training process, only one model and one type of image will be used. Therefore, the `LLM` column will always be `Gemma3-27B`, `Prompt` will be `Normal`, and `Distressed` will be `False`. The output CSV file will be stored at `{data_dir}{mock_data_test_output}_Hospitalfinal.csv`.

The example output columns and values will be: 
```
"LLM": model_name.split("+")[0],
"False Positives": fp,
"False Negatives": fn,
"Incorrect Extractions": ic,
"Correct Matches": correct_matches,
"Precision": precision,
"Recall": recall,
"F1score": f1score,
"Accuracy": accuracy,
"Parsed": True,
"Hospital": hospital, 
"Prompt": prompt,
"Distressed": False
```

parameter settings:
```
data_dir = "/u/lsong/labspace/lei_notebook/data/" # directory containing the predicted responses and expected reports
mock_data_test_output = "output_gemma-3-27b-it_1000ct.pkl" # name of the pickle file containing the predicted responses and expected reports
```

### 5.2 Visualizing F1 Score distributions
This step is running in a jupyter notebook.

The code for generating the histogram is located in cell #6 of `PDF_benchmarking/getJSON/compareJSON_linghao.py`. 

The inputs will be all the CSV files from different attempt that expected to compared.
The output will be a histograph printed in the notebook.

### 5.3 Visualizing loss scores
This step is running in a jupyter notebook.
Jupyter notebook at: `/u/lsong/labspace/git_repo/PDF_benchmarking/graphs/PlotF1.ipynb` #7 cell

Cell #7 contains a line plot showing both the training loss and evaluation loss extracted from `training.log`. The training log is generated during the LoRA training process and is stored in the same directory of the LoRA **directory** (note: this is the `lora_output_dir` in 2.2, not the safetensor file). Typically, the evaluation loss is expected to be lower than the training loss, indicating that the model is not overfitting and is performing well on unseen data.

The inputs will be the `/.mounts/labs/courtotlab/scratch/lora/training.log`
The output will be a curve plot printed in the notebook.
